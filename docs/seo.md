# SEO, AEO & GEO

How the OtterBeer site gets found — by Google (SEO), by answer engines
extracting a direct answer (AEO), and by LLMs deciding what to say and cite
about the brand (GEO).

Three rules hold the whole thing together. Break one and the rest stops
working:

1. **Everything a crawler needs must be in the server-rendered HTML.** Not the
   RSC payload, not after hydration. `curl` the page and read what comes back.
2. **Brand facts live in one place.** `src/config/brand.ts` for NAP/socials,
   `src/config/faq.ts` for the FAQ. Every consumer — footer, contact section,
   JSON-LD, `llms.txt` — reads from those, so the visible page and the
   structured data can never disagree.
3. **`NEXT_PUBLIC_SITE_URL` must be the real origin in production.** Every
   canonical, hreflang, sitemap `<loc>`, OG image and `@id` is built from it.
   `src/lib/env.ts` refuses to boot in production if it is still localhost.

---

## The thing that mattered most

`AgeGateWrapper` used to `return <AgeVerificationGate />` *instead of*
`children` when unverified. Its server snapshot is always "unverified", so the
server-rendered HTML of every marketing page was the age gate and nothing else
— about 7KB of "ARE YOU 18+?" where the page should have been. No hero, no
products, no FAQ, no footer, and no `<script type="application/ld+json">`
either: the structured data existed only inside the RSC flight payload, escaped
as a JSON string, which no crawler parses.

The gate is now an **overlay**: `children` always render and the prompt sits on
top until the visitor confirms. Same content to crawlers and to people, so it
is not cloaking. It still blocks: opaque full-screen overlay, `inert` on the
page behind it (no clicks, no tab focus, out of the a11y tree), body scroll
locked.

Homepage HTML a crawler receives went from **7.5KB to ~80KB**.

`tests/e2e/public/seo.spec.ts` asserts this against the raw response so it
cannot regress silently.

## SEO

| Concern | Where |
|---|---|
| `metadataBase`, title template, robots directives, icons, theme colour | `src/app/layout.tsx` |
| Per-page title/description/canonical/hreflang/OG | `buildStaticPageMetadata` in `src/lib/seo.ts` |
| Homepage metadata | `buildHomeMetadata` — sets `absoluteTitle` so the brand isn't printed twice |
| `/sitemap.xml` | `src/app/sitemap.ts` |
| `/robots.txt` | `src/app/robots.ts` |

**hreflang.** `staticAlternates()` emits every supported locale plus
`x-default` (pointing at the Vietnamese original). Without `x-default`, `/` and
`/en` compete for the same query.

**The proxy.** `src/proxy.ts` rewrites unprefixed paths to `/vi/...`. Its
matcher must exempt the root-level metadata routes — `sitemap.xml`,
`robots.txt`, `llms.txt` — or they get rewritten to `/vi/sitemap.xml` and 404.
This was the state of the sitemap before: present in the codebase,
unreachable in production.

**The social share card.** `OG_IMAGE_PATH` must point at an asset whose real
pixel dimensions equal `OG_IMAGE_WIDTH`/`OG_IMAGE_HEIGHT` (1200x630), because
Facebook, X and Zalo trust the declared numbers. It previously pointed at a
1024x1024 square published as 1200x630, so every shared link rendered a
mis-cropped preview. The card is generated by
`node scripts/generate-og-image.mjs` (pure Node, no `sharp`) — regenerate it if
the source art changes. `tests/unit/lib/publicAssets.test.ts` fails if the file
and the declaration ever disagree again, and also resolves every `/images/...`
path referenced anywhere in `src/` against `public/` — the check that would
have caught the four dead `contact-hero.jpeg` references.

**Breadcrumbs.** A page that emits `BreadcrumbList` JSON-LD must also render a
visible trail; Google's guidelines expect the markup to describe a breadcrumb
the user can actually see. Declare the trail **once** as a `BreadcrumbEntry[]`
and pass it to both `buildBreadcrumbJsonLd(locale, trail)` and
`<Breadcrumbs items={toBreadcrumbItems(locale, trail)} />`, so the two cannot
drift. For posts, `blogPostBreadcrumbTrail()` is that single source.

**Headings.** Exactly one `<h1>` per page. On the homepage that is the brand
heading in `HeroSection` — rendered `sr-only`, because the hero is
deliberately image-only and no type is drawn over the photography. It is one
honest sentence naming the brand, the category and the place, which is what
the images show; do not grow it into hidden keyword text, and do not delete it
because it "isn't visible" — it is the page's only statement of what it is.

Components that can appear both standalone and embedded take a heading-level
prop rather than hardcoding `h1` (`ContactSection.headingLevel`,
`AgeVerificationGate.layout`).

## AEO — being the answer

`src/config/faq.ts` → rendered by `FaqSection`, and emitted as `FAQPage`
JSON-LD by `buildFaqJsonLd`. One source, two consumers.

Each entry follows three rules:

- The question is phrased the way a person types it, not as a marketing header.
- The answer's **first sentence** answers it completely and survives being
  lifted out of context — that sentence is what becomes the snippet.
- The answer names checkable entities: the brewery, the province, the
  ingredients, the ABV/IBU, the year. Specifics can be grounded on; adjectives
  cannot.

`FaqSection` uses native `<details>`/`<summary>`, so every answer is in the
HTML whether or not the item is open. **Do not replace it with a JS accordion
that mounts answers on click** — that would delete the AEO value entirely.

## GEO — being cited

- **`/llms.txt`** (`src/app/llms.txt/route.ts`) — the beer specs live in a
  client-side carousel and the brand story in a flipbook widget, so a model
  that fetches the HTML without running JS sees little substance. This file is
  the opposite: no markup, no navigation, just facts. Generated from the
  configs and the DB so it cannot drift.
- **`robots.ts`** names the answer-engine crawlers explicitly (GPTBot,
  ClaudeBot, PerplexityBot, Google-Extended, …). Several are opt-in by
  convention. Flip a block to `disallow: "/"` to opt out.
- **`max-snippet: -1` / `max-image-preview: large`** in the root layout lift
  the caps on how much of a page an answer engine may quote.
- **The entity graph** below is what lets a model resolve "Otter Beer" to one
  real brewery rather than an ambiguous name.

## Structured data

One `@graph` per page with stable `@id`s, so nodes reference each other
instead of restating themselves (`jsonLdGraph` in `src/lib/seo.ts`).

| Page | Nodes |
|---|---|
| `/` | Organization, WebSite (+SearchAction), Brewery, one Product per beer, FAQPage |
| `/contact` | Organization, Brewery, BreadcrumbList |
| `/blog` | Organization, WebSite, BreadcrumbList |
| `/blog/[slug]` | Organization, WebSite, BlogPosting, BreadcrumbList |

`Brewery` is a `LocalBusiness` subtype — one node covers local-pack
eligibility, the NAP panel and the "where / when are they open" answer. Its
address is `ADDRESS` from `src/config/brand.ts`, the same object the footer and
contact section render, because a structured address that disagrees with the
visible one is the classic local-SEO trust penalty.

`Product` nodes carry ABV/IBU as `additionalProperty` — those numbers are
exactly what an answer engine lifts into a reply, and they are otherwise
locked inside a client-side carousel.

## Adding a page

1. `generateMetadata` → `buildStaticPageMetadata({ locale, path, title, description })`.
   Leave the brand out of the title; the root template appends it.
2. Add the route to `STATIC_ROUTES` in `src/app/sitemap.ts` — or, if it should
   not be indexed, pass `noIndex: true` **and** add it to `DISALLOWED` in
   `robots.ts`, and leave it out of the sitemap. Never both index and disallow.
3. Give it exactly one `h1`.
4. If it is a significant landing page, add a `BreadcrumbList` **and** render
   the matching visible `<Breadcrumbs>` from the same trail array (see
   "Breadcrumbs" above), and link it from the footer — the footer nav is how
   the crawler reaches pages the header doesn't list.
5. Give every content image a descriptive `alt`. `alt=""` is reserved for
   genuinely decorative images (WCAG H67) — a background texture, or an avatar
   whose subject is already named in adjacent text — and should carry a comment
   saying which. A *missing* `alt` is always a bug.

```bash
pnpm test tests/unit/lib/seoStructuredData.test.ts tests/unit/app
```

```bash
npx playwright test tests/e2e/public/seo.spec.ts tests/e2e/public/breadcrumbs.spec.ts tests/e2e/public/imageIntegrity.spec.ts
```
